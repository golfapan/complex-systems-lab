Splits, Metrics and Experimental Design

Which test would make a performance claim convincing?

The idea

Fit preprocessing only on training data, select settings using validation data and reserve an independent test for the final question. Splits should reflect how future examples differ: by time, person, machine or location when appropriate.

Choose metrics that represent the costs of mistakes. Accuracy can hide severe minority-class failure. State the decision threshold, sample size and uncertainty, then compare with a baseline and controlled alternatives. The evaluation protocol should be designed before looking for the best-looking result.

Read the relationship

precision=TP/(TP+FP); recall=TP/(TP+FN)

TP counts true positives, FP false positives and FN missed positives. The formulas require a defined positive class and meaningful handling of zero denominators.

Work through an example

  1. Among 100 cases, suppose only one is positive.
  2. Predicting every case negative gives 99% accuracy but zero positive recall.
  3. A useful protocol therefore examines missed positives and false alarms rather than praising accuracy alone.

When it applies

Metrics from correlated cases do not have the same uncertainty as equally many independent cases. Test leakage and repeated tuning can invalidate otherwise correct arithmetic.

Check your understanding

Why must scaling statistics be fitted on training data only?

Using held-out statistics lets information from the evaluation set influence the trained pipeline.
