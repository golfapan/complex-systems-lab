Inference: Prefill, KV Caches and Quantisation

How can a trained language model generate tokens efficiently?

The idea

Prefill processes an existing prompt. Decoding extends it one token at a time. A key–value cache avoids recomputing earlier attention keys and values, but its memory grows with the retained context and the number of active sequences.

Quantisation reduces representation precision and storage. Its speed benefit depends on kernels, hardware and workload; quality must be measured as well. Static weight memory, cache memory and temporary activations are separate parts of deployment accounting.

Read the relationship

KV bytes≈2×layers×batch×length×KV heads×head width×bytes per element

The factor two counts keys and values. Different attention layouts, cache formats and sharing conventions change the calculation.

Work through an example

  1. Use one layer, one sequence, length 100, two KV heads, width four and two-byte elements.
  2. The simple formula gives 2×1×1×100×2×4×2=3,200 bytes.
  3. Doubling context doubles this cache estimate even though model weights are unchanged.

When it applies

Report time to first token, later-token latency, throughput and task quality separately. One speed figure cannot represent every batch or context length.

Check your understanding

Does halving weight precision necessarily halve total inference memory?

No. The cache, activations and runtime buffers may account for a substantial fraction.
