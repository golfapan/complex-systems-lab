A Training Loop You Can Debug

How can you tell whether a network is actually being trained?

The idea

A training loop connects data, prediction, loss, gradient calculation and parameter updates. Keep each stage visible enough to inspect. Validation then tests the current model on held-out data without using those results as training examples.

Start with an intentionally tiny problem. Fitting a handful of examples is a useful diagnostic before a large run. Reproducible experiments preserve the configuration, data split and checkpoint state, including optimiser state when continuing training. A long runtime is not evidence that the right computation occurred.

Read the relationship

clear gradients → forward → loss → backward → update → validate

A training iteration is one update cycle. An epoch is a pass through a dataset; neither is a layer or a sequence timestep.

Work through an example

  1. Ask a small model to fit eight labelled examples.
  2. If it fails, check label alignment, the loss interface, optimiser parameter membership and whether gradients exist.
  3. Then enlarge the dataset and compare training with validation curves instead of merely extending the run.

When it applies

Validation data guide model selection and are not an untouched final test. Evaluation mode does not itself prevent accidental data leakage.

Check your understanding

Which state is missing if weights resume correctly but momentum changes after a restart?

The optimiser's memory was not restored; a training checkpoint needs more than model weights.
