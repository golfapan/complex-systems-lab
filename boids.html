从一个有趣的问题开始

鸟群转弯时，谁在喊口令？

傍晚一群鸟突然转向，几乎像同一块会流动的布。可是每只鸟只看得见身边一小部分伙伴，未必知道整群要去哪里。假如你是一只鸟，只遵守三件小事：别撞上、跟邻居朝同一方向、别掉队，整群能自己组织起来吗？在这里没有领队，你可以逐条关掉规则，看看秩序怎样出现，又怎样消失。

先猜一猜：只有“别撞上”这一条，能不能让大家一起飞？先试只管避让，再加入对齐。

演化中…

点击选择一只鸟（粉色），它只是观察对象，不会领导鸟群。上下、左右边缘相接；鸟从一边离开会从另一边回来。

HOW IT WORKS

局部互动，怎样变成整体秩序？

01 · 先定义：这只鸟的“状态”是什么？

这是一套二维、局部感知、恒速的行为规则。它把“避开近邻、跟随朝向、靠近同伴”写成可计算的关系，没有真实鸟的质量、升力或空气阻力。这里的转向加速度是设计出来的响应规则，不是已经测定的自然力。

把第 n 步的第 i 只鸟写成位置向量 xᵢⁿ 和速度向量 vᵢⁿ；上标 n 是时间步编号，不是乘方，下标 i、j 是鸟的编号。粗体或带两个分量的量都是二维向量，|z| 表示向量长度。画布横向向右、纵向向下为正。

符号、含义与本页默认值
符号含义单位／默认值
xᵢⁿ=(x,y)位置，下面统一简写成 (x,y) 两个分量画布单位；横向 0～1000，纵向 0～700（不含右端点）
vᵢⁿ=(vₓ,vᵧ)当前速度；既有方向，也有大小画布单位／模型秒
v₀飞行速度滑条设定的速率，是一个标量默认 75；可调 20～140
Δt每个计算小步的模型时间固定 1/60 模型秒
R；rₛ感知半径；分离作用距离R 默认 85，可调 30～160；rₛ 固定 26
wₛ；wₐ；w꜀分离、对齐、聚拢的权重，无量纲“一起飞”预设为 1.5、1.2、0.7
Aᵣ；Aₜ每条转向建议、合成转向的长度上限固定 120、220 画布单位／模型秒²
sᵢⁿ；ℓᵢⁿ；cᵢⁿ分离、对齐、聚拢给出的转向加速度建议；ℓ 是字母 ell每一步重新计算的二维向量
aᵢⁿ三条建议合成后的总转向加速度始终指总量，不再用 aᵢ 兼指对齐项

“一起飞”等预设只重设三个权重。若之前改过速率、感知半径或鸟数，这些设置会保留；表中列的是初次载入默认值。模型秒是本模拟的时间尺度，不表示已经与真实鸟的秒、米做过标定。

每只鸟的位置、速度作为状态传到下一步；三条建议与总加速度都在本步从零重算。建议不会作为独立的记忆量存下来，更不会把上一步的建议直接加进本步建议；它们的影响通过更新后的位置和速度传到未来。

02 · 第 0 步：用同一份旧状态找邻居

下面每个 n 都表示“本步开始时”。所有鸟先读取这份旧状态，各自算出下一步，最后一起更新，不会让先计算的鸟把新位置提前传给后计算的鸟。

rᵢⱼⁿ 是“从鸟 i 指向鸟 j”的最短周期位移，dᵢⱼⁿ 是它的长度。这两个符号分别表示向量与标量距离，不能混用。下式的坐标分量 xᵢ、yᵢ 等都取自第 n 步，为简洁省略时间上标。

rᵢⱼⁿ = ( P1000(xⱼ−xᵢ), P700(yⱼ−yᵢ) )
dᵢⱼⁿ = |rᵢⱼⁿ|
PD(z) = z−D（z>D/2）；z+D（z<−D/2）；z（其余）

例如 i 在 (995,100)，j 在 (5,100)，横向最短位移是 +10，不是 −990。PD 是“找近路”；最后更新位置用的 B 是“回到画布”，两者用途不同。

Nᵢⁿ = { j≠i：ε < dᵢⱼⁿ < R }
Mᵢⁿ = { j∈Nᵢⁿ：dᵢⱼⁿ < rₛ }，rₛ=26
mᵢⁿ = |Nᵢⁿ|，ε=10⁻⁹

Nᵢⁿ 是所有可见邻居，Mᵢⁿ 是其中要避让的近邻；mᵢⁿ 是邻居数量。当前代码用严格小于，因此距离恰好等于 R 或 26 的点不纳入对应集合；自己和距离接近零的重合点会被跳过。

第 1 步 · 分离：近邻各贡献一个“远离它”的向量

qₛ,ᵢⁿ = Σj∈Mᵢⁿ ( −rᵢⱼⁿ / (dᵢⱼⁿ)² )

负号表示背离邻居。若一个邻居在右方 10 个单位，r=(10,0)，它的贡献是 (−0.1,0)；右方 20 个单位的贡献是 (−0.05,0)。虽然分母是距离平方，单个向量的大小是 d/d²=1/d，所以它不是大小按 1/d² 变化的库仑力。多个邻居的贡献先相加，也可能彼此抵消。

第 2 步 · 对齐：取邻居速度的向量平均

qₐ,ᵢⁿ = (1/mᵢⁿ) Σj∈Nᵢⁿ vⱼⁿ　（mᵢⁿ>0）

这里平均的是速度向量，不是角度数字；两个相反速度会抵消。它只给出一个希望跟随的方向，还不是最终对齐加速度 ℓᵢⁿ。

第 3 步 · 聚拢：取邻居相对位移的向量平均

q꜀,ᵢⁿ = (1/mᵢⁿ) Σj∈Nᵢⁿ rᵢⱼⁿ　（mᵢⁿ>0）

这是“邻居相对我在哪里”的平均，指向局部相对中心。跨边界时先取每条最短位移再平均；不能直接平均邻居的绝对坐标。

qₛ,ᵢⁿ、qₐ,ᵢⁿ、q꜀,ᵢⁿ 是三个原始方向输入，含义与单位不同，不能直接相加。没有对应邻居时，相关 q 定为零；下一步会把它们分别转换成同类的转向建议。

03 · 第 4 步：方向 → 期望速度 → 转向建议

三条规则共用同一个函数 Tᵢⁿ(q)。对于非零方向 q，先沿 q 设定一个大小为 v₀ 的期望速度，再与当前速度相减。

u(q) = v₀ · q/|q|
Tᵢⁿ(q) = limit( [u(q)−vᵢⁿ]/τ, Aᵣ )
τ=1 模型秒，Aᵣ=120
sᵢⁿ = Tᵢⁿ(qₛ,ᵢⁿ)
ℓᵢⁿ = Tᵢⁿ(qₐ,ᵢⁿ)
cᵢⁿ = Tᵢⁿ(q꜀,ᵢⁿ)

τ 是把速度差换成转向加速度的响应时间尺度。本代码直接把速度差当作转向量使用，相当于这里取 τ=1；它没有独立的 τ 参数或滑条。这样写是为了让“速度差”和“加速度”的单位关系明确，计算数值与代码一致。

limit(z,L) = z　　　　　　　（|z|≤L）
　　　　　 = L · z/|z|　　　（|z|>L）

限幅只缩短过长的向量，不改方向；不是分别把横纵分量截成 ±L。如果 |q|<10⁻⁹，代码直接返回零建议，不做除法，也不把“无建议”解释成“期望速度为零，所以要刹车”。权重为零时也跳过对应规则。

距离更近先改变分离的合成方向；它不保证最终转向建议更大。例如只有同一个方向的一只近邻，从距离 20 变成 10，原始贡献会加倍，但归一化后的方向相同，算出的 sᵢⁿ 也相同。三条建议还受自身速度与 120 限幅影响。

04 · 第 5～6 步：加权、总限幅，再更新

权重无量纲，先放大或缩小各自的建议。三项合成后，再限制总长度；这两次限幅的顺序不能交换。

aᵢⁿ = limit( wₛ sᵢⁿ + wₐ ℓᵢⁿ + w꜀ cᵢⁿ, Aₜ )
Aₜ=220
ṽᵢ = vᵢⁿ + Δt · aᵢⁿ
vᵢⁿ⁺¹ = v₀ · ṽᵢ/|ṽᵢ|
xᵢⁿ⁺¹ = B( xᵢⁿ + Δt · vᵢⁿ⁺¹ )

ṽᵢ 是尚未恢复速率的临时速度。下一行将它恢复到设定的 v₀；最后用新速度移动位置。B 对横坐标按 1000、纵坐标按 700 取正的周期余数，例如 x=1002 回到 2，x=−2 回到 998。正常页面设置下临时速度非零，归一化可用。

若没有任何邻居，则三条建议和 aᵢⁿ 都为零，方向保持；当滑条刚改过速率时，下一步仍会把速度大小恢复为新的 v₀。平时速率固定为 v₀，三条建议的最终作用体现为转向；不应把这种恒速处理读成守恒的牛顿力学。

这些式子说明的是本页实际离散更新算法。模型具有邻域切换、限幅、归一化和周期边界，不是某条连续微分方程的精确解。

05 · 完整算一次：一只鸟、两只邻居

用“一起飞”的权重 (1.5,1.2,0.7)，取 v₀=75、R=85、Δt=1/60。自己位于 (100,100)，速度 (75,0)；邻居甲位于 (110,100)，速度 (0,75)；邻居乙位于 (100,120)，速度 (75,0)。三只鸟的速率都是 75。这是固定算例，不是粉色鸟的实时读数。

① 找邻居并计算三个原始输入

两条位移为 rᵢ甲=(10,0)、rᵢ乙=(0,20)，距离为 10、20；它们都小于 26 和 85，所以两只邻居都参与三条规则。

qₛ,ᵢ = (−10,0)/100 + (0,−20)/400
　　 = (−0.10,−0.05)
qₐ,ᵢ = [(0,75)+(75,0)]/2 = (37.5,37.5)
q꜀,ᵢ = [(10,0)+(0,20)]/2 = (5,10)

② 各自转换成转向建议

期望速度 → 减当前速度 → 单条限幅；数值保留两位小数
规则期望速度 u(q)[u(q)−(75,0)]/τ长度限幅后的建议
分离 sᵢ(−67.08,−33.54)(−142.08,−33.54)145.99 > 120(−116.79,−27.57)
对齐 ℓᵢ(53.03,53.03)(−21.97,53.03)57.40 < 120(−21.97,53.03)
聚拢 cᵢ(33.54,67.08)(−41.46,67.08)78.86 < 120(−41.46,67.08)

只有分离项在这里触及单条 120 限幅。其余两项保留原值；“对齐或聚拢一定很小”不是通用结论。

③ 加权后再限总长度

1.5 sᵢ + 1.2 ℓᵢ + 0.7 cᵢ
≈ (−230.566,69.242)，长度 ≈ 240.739 > 220
aᵢ = (220/240.739) · (−230.566,69.242)
　≈ (−210.704,63.277)

④ 更新速度与位置

ṽᵢ = (75,0) + (1/60) · (−210.704,63.277)
　≈ (71.488,1.055)，长度 ≈ 71.496
vᵢⁿ⁺¹ = 75 · ṽᵢ/|ṽᵢ| ≈ (74.992,1.106)
xᵢⁿ⁺¹ = (100,100) + (1/60) · vᵢⁿ⁺¹
　　　≈ (101.250,100.018)

新速度长度仍是 75，方向稍微向右下偏转。这里未越过边界，B 不改变位置。下一步要从新的位置、速度重新找邻居并重算三条建议，不能直接沿用本次 q、s、ℓ、c 或 a。

计算过程使用未四舍五入的中间数值，表格仅作阅读展示。若边算边使用表内两位小数，末位可能略有差别。

06 · 动画下方的“朝向一致度”怎样算？

每只鸟的单位朝向 eᵢ = vᵢ / |vᵢ|
平均朝向 ē = (e₁ + … + eN) / N
朝向一致度 Φ = |ē|，范围 0～1

全部向右，平均向量长度为 1；一半向右、一半向左会抵消，结果为 0；两只鸟一只向右、一只向下，结果为 √2/2≈0.707。它只衡量全体方向是否一致，不衡量挤得多紧，也不能直接说明是否碰撞或是否分成多个小群。

时间是已推进的模拟时间，每个单步增加 1/60 s；鸟数是当前个体数。播放倍率只改变推进节奏，不是鸟的飞行速度，也不改变这三个转向向量的计算公式。

07 · 逐条关闭规则，看看解释是否成立

“朝向一致度”是单位速度向量平均值的长度，范围 0～1。接近 1 表示大多数鸟朝向一致；接近 0 也可能是两群反向飞行，不等于完全无序。

  1. 先选“一起飞”，观察局部小群是否逐渐协调。
  2. 选“只管避让”，保留碰撞回避，去掉对齐和聚拢，比较整体方向。
  3. 把对齐从 0 慢慢增加，再扩大感知半径，观察秩序是否更容易形成。
  4. 强聚拢可能让鸟过度集中；分离与聚拢之间的竞争决定群的尺度。

速度较快、感知范围过小或离散步长太大时仍可能交叠；这不是严格的无碰撞控制器。没有真实空气动力、障碍物或训练过程。

辅助阅读 · 从 Boids 到机器人工程（点击展开）

带着三个问题读下面的材料：状态是什么？谁提供观测？控制目标从哪里来？本页没有全局领队或指定队形，每只鸟的转向目标随邻居改变；工程系统则还可能有目的地、期望相对队形、传感误差和安全约束。

完整状态 zᵢⁿ = (xᵢⁿ,vᵢⁿ)
局部控制：由自己与邻居的旧状态计算 aᵢⁿ
状态递推：zᵢⁿ⁺¹ = F(zᵢⁿ,aᵢⁿ)

这里新增 z 表示位置与速度组成的完整状态，x 仍只表示位置；F 包含上文的恒速与周期边界操作。下面的对应关系是帮助迁移理解的类比，不能直接移用另一套算法的结论。

  1. 状态递推 → 轨迹优化与 MPC

    共同点是用状态和控制预测下一步。MPC 还会在预测时域内优化一串动作、执行第一步并重新规划；本页 Boids 直接使用三条局部规则，没有这一步优化。

    MIT · Russ Tedrake · Trajectory Optimization ↗ 在线教材；先读 Problem Formulation，再读 Model-Predictive Control。

  2. 已知状态的控制 → 有观测误差的估计与 SLAM

    本页直接读取模拟器里邻居的位置、速度。SLAM 要从运动与观测信息中联合估计自身位姿和地图，可用滤波或图优化。只给邻居观测加噪声、延迟会引出状态估计问题；还不能因此称为 SLAM，后者另有建图与联合估计任务。

    MIT · Visual Navigation（VNAV）公开讲义目录 ↗ 先看第 16–17 讲估计，再看第 23–24 讲 SLAM、因子图与边缘化。

  3. 分离与聚拢 → 人工势场路径规划

    “避开近处、靠向目标”的方向直觉可以对照人工势场阅读。本页聚拢的目标由邻居形成，没有固定终点或障碍物规划；加上对齐、归一化与限幅后，也不能把整套 Boids 直接当作某个势能的梯度下降。

    Stanford · Oussama Khatib · CS225A Artificial Potential Field ↗ PDF 讲义；从第 6 页的人工势场部分开始看吸引、排斥与运动规划。

  4. 局部对齐与聚拢 → 一致性、协作与编队控制

    共同的问题是“只用局部信息，怎样协调群体？”工程编队通常还指定相对位置或朝向，并处理感知、通信与动力学。本页 Φ 接近 1 只说明朝向一致，不代表已实现指定队形、证明一致性收敛或保证无碰撞；120/220 的行为限幅也不等于真实执行器模型。

    Stanford MSL · Vision-Based Distributed Formation Control Without an External Positioning System ↗ 2016 年论文摘要与书目信息；把相对朝向、相对位置的一致性控制与视觉/IMU 估计接起来看。
